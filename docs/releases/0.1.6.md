# Release 0.1.6

## Contents

- A sidecar keeps the spelling it has on disk, so a photo whose sidecar is
  `DSC_0001.XMP` no longer has Apature read, write or copy `DSC_0001.xmp`.
- A self-installed update is checked before it counts: the downloaded disk image
  must match the SHA-256 its release notes publish, the image is attached with
  its checksum verified, and the old app is kept until the new one opens.
- The thumbnail cache keeps itself to 2 GB, dropping the oldest thumbnails at
  startup, so a large library cannot fill the disk.
- Warm-up leaves a decode thread free, so a row that scrolls into view is
  decoded straight away even while a folder warms in the background.
- An update that cannot copy the new app leaves the old one where it was.

## Steps

1. Version-bump commit on main: Cargo.toml, Cargo.lock, CHANGELOG.md, this file.
2. Tag v0.1.6 on the bump commit. The release workflow builds the DMG on a macOS
   runner, computes its SHA-256, and attaches both to the release.
3. Verify the release page shows Apature-0.1.6.dmg and its SHA-256.
4. Download the DMG and launch it once on a Mac that did not build it.
