# Release 0.1.10

## Contents

- No change to what the app does. This build is cut from the current `main`,
  so its build number matches the tree; the app itself is the same as 0.1.9.
- The checks that guard a release are the only difference.
  `tools/check-release-rules.sh` now reads the dated changelog heading as a
  heading rather than as prose, so a version bump stops warning about the em
  dash REL-10 asks for. `docs/RELEASES.md` says so next to REL-9.

## Steps

1. Version-bump commit on main: Cargo.toml, Cargo.lock, CHANGELOG.md, this file.
2. Tag v0.1.10 on the bump commit; the release workflow builds and attaches the DMG.
3. Verify the release page shows Apature-0.1.10.dmg and its SHA-256.
4. Download the DMG and launch it once on a Mac that did not build it.

## Notes

- Why a release at all: the owner asked for a build from the current `main`.
  Nothing user-visible changed, so the changelog carries one line that says the
  build number moved and points at the release checks.
- Ad-hoc signed (no Developer ID secrets on this fork); the first launch needs
  right-click Open.
- Steps 3 and 4, and the REL-30 screenshot, need a Mac and were not done away
  from one.
