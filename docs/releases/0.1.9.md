# Release 0.1.9

## Contents

- Saving marks into a JPEG no longer fails on a volume that has no access time,
  such as some network and FUSE mounts. The photo keeps its modified date and
  the mark is written.
- Three audit fixes ride along. The two below only fire on a damaged or
  shortened file: a truncated IPTC block and a JPEG header that another tool
  cut short now read as malformed instead of indexing past the end of the
  segment.

## Steps

1. Version-bump commit on main: Cargo.toml, Cargo.lock, CHANGELOG.md, this file.
2. Tag v0.1.9 on the bump commit; the release workflow builds and attaches the DMG.
3. Verify the release page shows Apature-0.1.9.dmg and its SHA-256.
4. Download the DMG and launch it once on a Mac that did not build it.

## Notes

- Only the first item in Contents is user-visible, so the changelog names only
  it. `iim::from_app13` has no product caller and `export::splice_after_app0`
  only fails on encoder output that is already malformed.
- The disk image is ad-hoc signed (no Developer ID secrets on this fork); the
  first launch needs right-click Open.
- Steps 3 and 4, and the REL-30 screenshot, need a Mac and were not done away
  from one.
