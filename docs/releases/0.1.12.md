# Release 0.1.12

## Contents

- Copying photos to an exFAT card or drive works again. Those volumes refuse the
  hard link Apature used to put a finished copy in place, so every photo failed
  with "Operation not supported (os error 45)"; the copy now finishes without
  that link and still never replaces a file that is already at the destination.
- A copy that does fail says which step failed and on which file, and a volume
  that cannot fully honour a flush is reported as a weaker sync instead of
  failing the photo.

## Steps

1. Version-bump commit on main: Cargo.toml, Cargo.lock, CHANGELOG.md, this file.
2. Tag v0.1.12 on the bump commit; the release workflow builds and attaches the DMG.
3. Verify the release page shows Apature-0.1.12.dmg and its SHA-256 (REL-22).
4. Download the DMG and launch it once on a Mac that did not build it.

## Notes

- One fix in three parts: copy errors now name the step and the file, a refused
  full flush degrades to fsync, and a refused hard link publishes through a
  destination created exclusively. The tests covering them pass on Linux and on
  macOS; the fallback is proven against an injected ENOTSUP, not a real exFAT
  volume, so the first ingest to the T7 is worth watching.
- The disk image is ad-hoc signed when the Developer ID secrets are absent; the
  first launch then needs right-click Open.
- Steps 3 and 4 need a Mac and were not done away from one.
