# Release 0.1.11

## Contents

- The five fixes from the 2026-11-04 audit that a person can run into:
  - A paste and a caption for the same photo no longer lose the older one's
    fields. Partial metadata saves are merged field by field, and every photo a
    bulk job folded into a merged save reports back, so the job finishes.
  - Sidecar and JPEG temporary names are unique per save, not per app, so the
    mark writer and an ingest pad writing one file cannot share a scratch file.
  - Delivered part names are unique per process, so two copies of Apature
    sending the same file cannot interleave bytes into one upload.
  - The temporary file a crashed Replace leaves behind is cleared, so the next
    Replace no longer fails with a confusing destination-exists error.
  - A rename that finds a staging file stranded by an interrupted run fails and
    rolls back instead of overwriting it.
- No new features and no interface changes.

## Where the changelog line came from

- The audit's changelog line was committed on `main` under the `0.1.3` section,
  which made those fixes read as fixes from 0.1.3. This bump moves that line out
  of 0.1.3 and rewrites it in the dated 0.1.11 section, one line per fix, so the
  notes for this build describe this build (REL-7, REL-10).

## Steps

1. Version-bump commit on main: Cargo.toml, Cargo.lock, CHANGELOG.md, this file.
2. Tag v0.1.11 on the bump commit; the release workflow builds and attaches the DMG.
3. Verify the release page shows Apature-0.1.11.dmg and its SHA-256.
4. Download the DMG and launch it once on a Mac that did not build it.
